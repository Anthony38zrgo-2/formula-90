======================================================================
12. DEFINE FOUR SEPARATE CONCEPTS
======================================================================

--------------------------------------------------
A. strong_usage
--------------------------------------------------

Any call whose model tier is classified as strong/high-capacity.

This is purely descriptive.

Example:

    Terra
    Sol

depending on current model policy.

Formula:

    strong calls / total calls


--------------------------------------------------
B. automatic_escalation
--------------------------------------------------

A strong call caused by runtime escalation policy.

Examples:

    attempt_budget_exhausted
    repeated failure
    architecture uncertainty detected by router

This must be derived from routing semantics, NOT simply from model tier.


--------------------------------------------------
C. manual_override
--------------------------------------------------

The user explicitly selected a model different from automatic/planned routing.

Existing:

    routing_source = user_override

belongs here.


--------------------------------------------------
D. planned_capacity
--------------------------------------------------

A model with higher capacity is chosen BEFORE implementation because planning
determined the task requires it.

Example future flow:

    PO classifies task L
        ↓
    Terra high from attempt 1

This is NOT an escalation.

The system must support this semantic category now even if Execution Contracts
are not implemented yet.
