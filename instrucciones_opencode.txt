# Implement ANL-001 — Deterministic Headless Blender 3D Analysis Suite

## Mission

Build the repository's reusable 3D analysis suite now, before further vehicle,
vegetation, trackside or Blender-driven features depend on ad-hoc scripts.

Create it under:

```text
blender/analysis_suite/
```

The suite must turn a geometric question into deterministic, machine-readable
evidence. It is an **analysis and validation** tool: it must never mutate a
source asset, scene, texture, tracked GLB, OBJ or `.blend` file. It may write
only requested JSON reports and temporary test fixtures.

This is an implementation task, but do not stage, commit, revert, delete or
otherwise alter unrelated shared-worktree changes.

## Mandatory repository facts and reuse policy

Existing assets must be preserved and reused; do not create competing parsers:

```text
blender/vehicle_pipeline/inspect_glb.py
blender/vehicle_pipeline/tests/test_inspect_glb.py
blender/vehicle_pipeline/README.md
blender/vehicle_pipeline/examples/deep_analysis_k3.py
blender/obj_validator/
```

Current state of these inputs:

- `inspect_glb.py` is a stdlib GLB structural inspector with hierarchy-aware
  bounds, primitive attribute coverage, normal statistics, scale/determinant
  evidence and JSON output.
- `test_inspect_glb.py` verifies its core GLB behaviors with self-created tiny
  fixtures.
- `deep_analysis_k3.py` is a valuable Jordan-specific exploratory script, but
  contains hard-coded paths, datums, thresholds and semantic assumptions. It is
  an example only, not a production API.
- `obj_validator/` already owns existing OBJ/MTL validation and repair behavior.
  Do not copy, rewrite or invoke its repair functions from this suite.

The new suite must import/wrap `inspect_glb.py` where suitable, and must offer an
OBJ adapter that calls the existing validator in read-only validation mode rather
than duplicating OBJ parsing. Record any pre-existing validator limitations in a
report; do not fix unrelated legacy code in this task.

Use repository-relative paths in configs, reports and docs. Resolve them against
the repository root discovered by walking upward from the executing script, not
the current working directory.

## Runtime contract

Support two deterministic modes:

1. **Pure Python mode** — no `bpy`; GLB/glTF structure and geometry evidence.
   Run with Blender 5.2's bundled Python:

```powershell
& "C:\Program Files\Blender Foundation\Blender 5.2\5.2\python\bin\python.exe"
```

2. **Blender headless mode** — only when a request needs evaluated scene/object
   transforms or Blender mesh facts. Run with:

```powershell
& "C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" --background --python ... -- ...
```

No GUI, interactive prompt, network request, package installation or current
working-directory dependency is allowed. Do not use the inaccessible
`blender/track_pipeline/.venv`.

Every CLI command must:

- emit one JSON object to stdout (deterministic key ordering);
- write an identical report to an explicit `--report` path when requested;
- use exit `0` for PASS, `1` for deterministic validation failure, `2` for
  invalid config/precondition/input, `3` for corrupt or unsupported asset;
- include suite version, command, normalized repository-relative inputs,
  SHA-256 input hashes, UTC-free deterministic metadata, findings, summary and
  exit-code explanation;
- sort lists/findings deterministically and avoid timestamps, random IDs and
  machine-specific absolute paths in report payloads.

### CLI commands

Implement these subcommands through one stable entry point:

```text
audit-glb       structural GLB inspection via the existing vehicle inspector
probe-geometry  transform-aware per-vertex predicate evidence for GLB geometry
validate-obj    read-only adapter to blender/obj_validator
probe-blend     optional headless Blender scene/object mesh and transform facts
vehicle-measure Formula90s vehicle-specific, config-driven measurements
```

The primary invocation must be:

```powershell
& "C:\Program Files\Blender Foundation\Blender 5.2\5.2\python\bin\python.exe" `
  blender\analysis_suite\scripts\run_analysis.py <subcommand> --config <repo-relative-json> --report <repo-relative-json>
```

`--help` must work without Blender and list the exit contract. Invalid config,
missing paths and unsupported extensions must return a JSON error with exit 2 or
3 as appropriate, never a traceback.

### Generic pure-Python capabilities

For `audit-glb`, return the existing inspector evidence instead of recomputing it.

For `probe-geometry`, implement config-driven, transform-aware predicates over
`POSITION` data:

- axis-aligned bounds and dimensions;
- finite positions;
- counts/indices per node, mesh and primitive;
- `above_axis`, `below_axis`, `ahead_of_axis`, `behind_axis`, `outside_band`,
  `inside_band`, and radial distance from a named centre/axis;
- optional named sections/ranges (for example front/rear/full); and
- a bounded deterministic sample of matching vertices: count plus lexicographically
  ordered index/value samples, never a full dump by default.

Predicate names, axes, centres, thresholds, coordinate convention and tolerance
must live only in config. Do not hard-code Jordan, FIA, Z-forward, millimetres or
metres in generic modules.

### Blender headless adapter

`probe-blend` must safely open a specified `.blend` in background mode without
saving it. It must report, for requested objects only: existence, type, world
transform, determinant, evaluated mesh vertex/triangle counts, local/world bounds,
material-slot names and finite-vertex evidence. It must clear evaluated meshes and
exit with the shared report contract. It must not render, import external assets,
modify the scene or save the file.

`scripts/blender_scene_probe.py` is the thin `bpy` implementation. The public CLI
must invoke it using the Blender executable and merge its JSON result. Unit tests
must remain runnable without `bpy`; an optional integration test may be skipped
cleanly if Blender is unavailable.

### Formula90s vehicle policy

`policies/vehicle.py` is an opt-in, config-driven layer. It may compose generic
predicate evidence into vehicle wording, but may not change generic semantics.

The example vehicle config must demonstrate K3's useful analysis concepts without
hard-coding them in code:

- source asset path and expected SHA-256;
- coordinate convention;
- named front/rear axle datums;
- height, width and overhang predicate sections;
- wheel centre/radial measurement;
- thresholds/tolerances;
- expected unit.

It must output `pass`, `fail`, or `not_measurable` per requested measurement.
`not_measurable` is never silently treated as pass. Do **not** encode FIA limits
or make legal-compliance claims in this implementation.

### OBJ adapter

`validate-obj` must document the exact command passed to the existing validator,
capture its deterministic result safely, and classify unsupported/non-JSON legacy
output as `not_measurable` or an explicit precondition failure. It must never run
`fix_obj.py` or any repair path. If adapting its output would require modifying
`blender/obj_validator/`, leave that directory unchanged and record the gap in
the suite discovery report.

## Tests and validation

Use `unittest` only. Tests must generate all temporary GLB fixtures in temporary
directories and leave no files behind. Test at minimum:

- repository-root discovery from a nested current directory;
- deterministic report serialization and stable finding order;
- every exit-code class;
- malformed/corrupt GLB handling;
- transformed GLB bounds and each predicate family;
- bounded vertex samples;
- config schema/precondition errors;
- vehicle policy returns `not_measurable` when source semantics do not support a
  requested measurement;
- `audit-glb` delegates to the existing inspector;
- OBJ adapter never selects a repair command.

Run and report:

```powershell
& "C:\Program Files\Blender Foundation\Blender 5.2\5.2\python\bin\python.exe" `
  -m unittest discover -s blender\analysis_suite\tests -v

& "C:\Program Files\Blender Foundation\Blender 5.2\5.2\python\bin\python.exe" `
  blender\analysis_suite\scripts\run_analysis.py audit-glb `
  --config blender\analysis_suite\configs\example_glb_audit.json `
  --report blender\generated\analysis_suite\example_glb_audit.json

& "C:\Program Files\Blender Foundation\Blender 5.2\5.2\python\bin\python.exe" `
  blender\analysis_suite\scripts\run_analysis.py vehicle-measure `
  --config blender\analysis_suite\configs\example_vehicle_measurement.json `
  --report blender\generated\analysis_suite\example_vehicle_measurement.json
```

Treat `blender/generated/analysis_suite/` as generated evidence: do not stage it.
Update `.gitignore` only if the directory is not already ignored; keep that edit
minimal and do not ignore source/tests/configs.
