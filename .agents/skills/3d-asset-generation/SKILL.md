# 3D Asset Generation & Modification

Use this skill for mesh analysis, low-poly generation, component discovery,
vertex/face changes, spatial queries, classification, colors, textures, UV
preparation, validation, and Godot-ready exports. Deterministic Python tooling
owns geometry whenever it can answer the question. Blender is a final-stage
tool, not the first opaque editing surface.

## Required Workflow

```text
INPUT ASSET
    -> INSPECT
    -> ANALYZE GEOMETRY
    -> CLASSIFY REGIONS
    -> PLAN MODIFICATION
    -> MODIFY
    -> VALIDATE
    -> COMPARE BEFORE/AFTER
    -> EXPORT
```

Never replace this with arbitrary edits, opening Blender, and iterating until
the asset merely looks acceptable. Read [analyze workflow](workflows/analyze.md)
before touching an unknown asset and use the smallest relevant workflow.

## Classification

Start every task with exactly one or more of:

```text
ANALYZE  MODIFY  SIMPLIFY  SEPARATE  GENERATE
TEXTURE  UV  VALIDATE  EXPORT
```

Route tools by responsibility:

| Need | Preferred tool |
| --- | --- |
| arrays, masks, vectors, transforms | NumPy |
| nearest neighbors, radius, propagation | `scipy.spatial.cKDTree` |
| mesh understanding, components, bounds, raycasts, surface proximity | Trimesh |
| cleaning, repair, decimation, remeshing, normals, vertex colors | PyMeshLab |
| simple procedural images and PNG | Pillow |
| advanced image masks, edges, segmentation, morphology | OpenCV |
| point clouds, ICP, registration, advanced geometry comparison | Open3D |
| complex materials, baking, scene assembly, final GLB/glTF | Blender headless |

Use Open3D only when it provides a concrete advantage over NumPy, SciPy, and
Trimesh. Before writing a Blender script, check whether PyMeshLab, Trimesh,
SciPy, or NumPy already provide the operation.

## Geometry First

Never modify unknown geometry blindly. The first report must include:

```text
file and format
object, vertex, face, and connected-component counts
bounding box, X/Y/Z dimensions, center, and approximate orientation
materials, UVs, vertex colors, and normals
disconnected components and manifold/non-manifold state where applicable
```

Use geometry to find a region. Object names are evidence only. Hardcoded vertex
indices are forbidden unless the model is generated by this pipeline and those
indices are an explicit stable contract.

For every automatic classification, emit `region`, `classification`,
`confidence`, and `evidence`. Build evidence from centroid, bounding-box sizes,
surface area, volume, vertex/face counts, distance to vehicle center, height,
orientation, symmetry, circularity, and aspect ratio. A low-confidence result
is a diagnostic result, not permission for a destructive modification.

## Spatial Queries

Use a KD-tree for relationships among vertices, centers, or regions:

```python
from scipy.spatial import cKDTree

tree = cKDTree(vertices)
distances, indices = tree.query(points)
neighbors = tree.query_ball_point(center, radius)
```

Do not implement nested distance loops when a KD-tree applies. KD-tree distance
to a vertex is not distance to a surface. For a real surface distance, query
triangles using Trimesh proximity/raycasting.

## Low-Poly Pipeline

```text
high/medium poly input
    -> clean
    -> remove degenerates
    -> identify components
    -> preserve important regions
    -> decimate
    -> recalculate normals
    -> validate silhouette
    -> UV
    -> vertex colors/textures
    -> GLB
```

Prioritize silhouette, proportions, recognizable body and aerodynamic elements,
wheel placement, and clean shading over microdetail. Every PyMeshLab filter must
be named, parameterized, applied to a working copy, measured, and validated.
Do not stack filters because the last result looked worse.

## Colors, Textures, and UV

Prefer vertex colors for flat low-poly colors, a small palette, and simple
assets. Use UV textures for logos, livery, numbers, patterns, and localized
detail. Keep geometry classification separate from image generation:

```text
classified geometry -> regions -> UV -> masks -> Pillow/OpenCV -> texture.png -> material
```

Use Pillow for simple procedural images and OpenCV only for advanced image
processing. Blender is permitted for UV/material operations when the Python
libraries cannot preserve the required data, but the choice must be recorded.

## Validation and Cache

After every relevant modification, validate vertex/face counts, components,
bounds, dimensions, normals, degenerate faces, duplicate vertices,
non-manifold edges, UV integrity, and material assignments. Compare BEFORE and
AFTER and classify the result as expected, unexpected, or inconclusive.

Never overwrite the source. Use `input/`, `working/`, `output/`, and `reports/`.
Analysis is cached by the asset SHA-256 at
`reports/<asset_hash>/analysis.json`. The reusable scripts are in
`.agents/skills/3d-asset-generation/scripts/`:

```powershell
tools\asset_pipeline\.venv\Scripts\python.exe .agents\skills\3d-asset-generation\scripts\analyze_mesh.py asset.glb --reports-dir reports
tools\asset_pipeline\.venv\Scripts\python.exe .agents\skills\3d-asset-generation\scripts\mesh_components.py asset.glb
tools\asset_pipeline\.venv\Scripts\python.exe .agents\skills\3d-asset-generation\scripts\spatial_query.py asset.glb --point 0 0 0 --radius 0.25
tools\asset_pipeline\.venv\Scripts\python.exe .agents\skills\3d-asset-generation\scripts\validate_mesh.py output.glb --compare-to asset.glb
```

The isolated dependency set is pinned in
`tools/asset_pipeline/requirements.txt`. The environment is not global.

## Blender Boundary

Use Blender headless only for complex materials, baking, visual validation,
scene assembly, format-specific conversion, or final GLB/glTF export that the
Python stack cannot perform correctly:

```text
blender --background --python script.py -- <parameters>
```

Do not use GUI-only edits as the source of truth. Preserve the input, record
the script and parameters, and validate the exported result again.

## Failure Protocol

If a modification fails twice or the result is geometrically unexpected, stop
brute-force parameter changes. Enter diagnostic mode:

```text
inspect -> analyze -> determine cause -> change strategy
```

Do not stack a workaround or claim visual success from automated geometry checks
alone. Visual acceptance still requires a human or image-capable reviewer.
