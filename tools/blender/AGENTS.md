# blender — Blender authoring scripts

Scope: Blender scripts remodeling, texturing, exporting, rendering, and validating the F1 vehicle meshes and liveries.
Consumers: the vehicle programs under `game/assets/models/vehicles/`.
Rules: scripts transform sources into regenerable outputs; review renders are evidence beside the sources they validate.

`validate_rear_suspension_chassis_clearance.py` audits physical rear suspension packaging against chassis geometry. Use the current physical profile and source geometry, evaluate the travel envelope and save evidence under `scratch/`. Include damper anchorage and moving linkage clearance. Keep cosmetic pose adjustments separate from physical geometry validation.

`generate_formula_one_2030_cockpit_headrest.py` writes preview sources and reports only under `scratch/`. Supply current steering and head-motion captures matching the current driver, modifier and camera configuration. The source generator preserves existing vehicle meshes and must retain closed topology. `cockpit_headrest_support_profiles.py` derives contact sections from the actual lining and interior surfaces. Fit the exterior upper seam to the cockpit opening contour and recess exposed padding beneath it; the historical rear height target yields to the latest user instruction to remain below the cockpit rim. Validate the sampled attachment edges, visible seam, exposed height limits and coverage of hidden support. Shared rim, lining and interior interfaces are intentional attachments. Other chassis intersections remain blocked. Minor animated head contacts below 12 millimeters and other driver contacts below four millimeters are allowed; extreme horizon poses are recorded independently. `capture_driver_head_motion_surfaces.gd` runs in an isolated Godot project containing current head-motion dependencies, without native runtime extensions. The vehicle source AGENTS.md documents preparation and the distinction between source verification and runtime export.

`raise_formula_one_2030_headrest_support.py` adds the subsequently authorized central rear circular crown to the preceding attached headrest. The 75 millimeter radius crown is the localized exception to the earlier exposed height limit; original attachment vertices and front recesses remain fixed. Use the preceding source and current steering and head-motion captures with --source-file, --output-directory, --driver-surfaces, --head-motion-surfaces and --radius-millimeters. The tool rejects repeated application and writes candidates and validation evidence under scratch/. Clearance checks must classify head poses against the original chassis without including the headrest under evaluation.

`export_formula_one_2030_headrest_assets.py` exports the headrest-bearing vehicle without saving changes to its authoring source. Supply --output-directory under scratch/ and --physics-profile. It bakes the headrest carbon color and tangent-space normal into embedded 2048 pixel textures using temporary normalized texture coordinates, then delegates chassis and wheel geometry export to export_f1_2030_v10.py. Validate the five candidates with validate_f1_2030_v10_glbs.py and compare all previously exported geometry attributes and material texture bytes before promotion. Preserve established body tangent values when exporter rounding differs. The canonical manifest and reports must record the promoted file hashes and authoring source hash.

trim_formula_one_2030_headrest_front.py shortens only the existing headrest using symmetric inclined cut planes and closes their end caps. Supply the preceding --source-file and a scratch --output-directory. The default plane in aligned Blender coordinates is longitudinal = -0.175 + 0.38 * absolute lateral, matching the supplied green marks. Preserve every other mesh, the rear crown and studio settings. The report distinguishes current closed geometry validation from historical animated clearance measurements.

extend_formula_one_2030_headrest_front.py supersedes the shortened front arms with symmetric extensions reaching approximately the longitudinal midpoint of the cockpit opening. Supply the preceding --source-file, the recorded --untrimmed-source-file containing the same rear crown, and a scratch --output-directory. The tool restores only the original headrest mesh, verifies the rear vertices, retains current unrelated meshes and studio settings, and moves the inclined cut planes forward by the measured extension. It rejects repeated application and incompatible restoration sources. Validate current driver posture, steering and configured head motion before promotion; historical captures cannot establish current clearance. Only the chassis export changes; preserve all four wheel exports byte for byte.

The later --taper-front-ends mode supersedes the broad midpoint end caps with long symmetric transitions toward the marked chassis rim region. The exposed terminal width is two millimeters at aligned longitudinal 0.185 meters. The extension tool performs the steep inclined cuts only forward of -0.12 meters, preserving the rear crown, without depending on the earlier trim tool. Regeneration still requires the preceding canonical source and compatible untrimmed restoration source. Current geometry, attachment and 250 driver samples are validated before source and chassis promotion.

fit_formula_one_2030_animated_driver_clearance.py supersedes the preceding minor-clipping allowances with a verified five millimeter margin around the current animated arms and configured head motion. It preserves headrest crown and attachments, driver anatomy and posture, exterior geometry and studio settings. Use recorded baseline source, chassis, manifest and matching current driver captures. The tool preserves existing surface triangulation before subtracting padded arm sweep volumes from the cockpit interior and seat. validate_formula_one_2030_animated_driver_clearance.py verifies conservative adaptive triangle-distance bounds, closed topology, absence of new geometry defects and retention inside the baseline occupied solids. Baseline seat self intersections remain explicitly identified. export_formula_one_2030_driver_clearance_assets.py replaces only the three fitted runtime primitives while preserving materials, embedded image bytes, every other mesh and the four wheel exports. All preview outputs belong under scratch/; fresh Godot steering and configured head captures must verify the exported candidates before promotion. The vehicle source AGENTS.md documents the complete arguments, reports and validation boundary.


The authorized descriptive object naming migration is defined by tools/blender/formula_one_2030_object_names.py. The source object_name_migration_manifest.json records previous and current names and preservation checks. Geometry, transforms, materials and wheel visual groups remain unchanged by this migration. Updated authoring tools normalize old source names in memory and normalize historical report references when reading them; historical reports retain their original provenance. Library imports must resolve either historical or current names before loading. Export selectors must include chassis assemblies and both wheel and brake assemblies through the central helpers. GEO_BRAKE_<POSITION>_CALIPER and GEO_BRAKE_<POSITION>_INBOARD_DUCT_COVER belong to BrakeStatic; the brake disc remains in SpinVisual. Canonical and Senna runtime assets received name-only JSON migrations preserving their binary geometry and embedded textures. Earlier color and pontoon edits remain in the authoring source and are not promoted by this rename operation. Source and runtime hashes describe distinct authoring and exported geometry snapshots.


Original tire geometry supersedes the preceding optimized tire surfaces. export_f1_2030_v10.py measures and duplicates the authoring data for every _TIRE object, ignoring formula_one_2030_runtime_surface_mesh for tires only. Other components retain their established runtime surface selection. restore_formula_one_2030_original_tire_geometry.py accepts --baseline-directory, --geometry-directory, --authoring-source-file and a scratch --output-directory; it replaces only tire geometry accessors while preserving materials, embedded images, wheel groups and other meshes. Export donor wheels from the canonical f1_2030.blend source for both liveries so their geometry remains shared. Every original tire has 23040 triangles. Validate all four tire widths and 335 millimeter radii, preserve the shared tire material import hook, update asset hashes and record the separate tire-source provenance before promotion.


The latest user request reactivates optimized tire surfaces and supersedes the preceding original-tire export policy. export_f1_2030_v10.py again selects formula_one_2030_runtime_surface_mesh when present. After the normal wheel-axis conversion, it measures the actual exported tire vertices and corrects only the tire width, both radial diameters and center; custom corner normals use the inverse transpose. Every active tire has 960 triangles, a 670 millimeter diameter on both radial axes and its configured width. Rims, brakes and other meshes retain their preceding geometry and transforms. restore_formula_one_2030_original_tire_geometry.py now accepts --surface-mode optimized or original to record the selected surface provenance. Use the canonical optimized donor for both liveries, preserve all material and image bytes, and validate exact exported dimensions before promotion.

export_formula_one_2030_brake_assets.py exports the current four brake assemblies to scratch candidates for both liveries. Run Blender with --python-exit-code 1 and pass a scratch output directory after --. It bakes carbon base-color maps into the wheel containers, replaces only disc, caliper and cover meshes, and adds one independent GEO_BRAKE_<POSITION>_DUCT under BrakeStatic. Chassis, tire, rim, hub, existing embedded images and their geometry bytes remain preserved. Validate eight structural meshes per wheel, three static brake parts and five rotating parts before promotion. The source file is never saved by this exporter.
