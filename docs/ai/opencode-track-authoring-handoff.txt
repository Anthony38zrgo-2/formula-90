# OBJECTIVE
Plan and implement a versioned local Track Authoring System for Formula90s.

The user must manually author the full track layout in a canonical SVG: centerline,
road parameters, elevation/banking controls, terrain zones, barriers, vegetation,
2D cards, grandstands, pit boxes, buildings, gameplay markers, and asset instances.
The system must normalize and validate the SVG, deterministically compile it through
Blender, and produce inspectable Blender output plus GLB runtime assets ready for
Godot. Every intentional save must retain a recoverable Git-tracked revision of the
specific track without capturing unrelated work.

# OBSERVED PROBLEM
The current La Chutana semantic-authoring pipeline is raster- and track-specific:
it uses semantic_layout.png, object_markers.png, object_catalog.json, and hard-coded
La Chutana validation counts. It has no local interactive editor, no SVG import
boundary, no general Asset Registry, and no revision model for author edits.

# EXPECTED BEHAVIOR
1. A user imports an external AI- or tool-generated SVG.
2. The server sanitizes and canonicalizes it into the restricted F90 Track SVG profile.
3. The editor lets the user edit all track-owned information and save an immutable,
   Git-tracked revision.
4. Validation normalizes the SVG to generated JSON and reports errors without Blender.
5. An explicit human-approved build checks the validated source hash, runs Blender
   headless, emits a .blend and scoped GLB outputs, validates them, then activates the
   build atomically for Godot.
6. Editor undo/redo and Git history can both restore a prior revision without
   destructive overwrite.

# FAILURE SIGNATURE
NOT APPLICABLE: this is a planned product, not an active runtime defect.

# VERIFIED FACTS
- The user confirmed SVG is the authoring interface: the user, not an AI, decides
  placement of trees, grass, and all other track-side content.
- The user requires editable centerline and banking in the MVP.
- Imported SVG can originate from AI image/SVG tools; it must therefore be treated as
  untrusted input and must not be built directly.
- Required outputs are GLB for Godot and a Blender format; the latter is a generated
  .blend inspection/interchange artifact, never a second editable source of truth.
- The editor controls the placement and parameters of registered assets. It does not
  edit internal GLB mesh/material geometry.
- Each edit/save must create a recoverable copy tracked in Git. Editor-level revert
  must be additive (new revision from old content), never destructive checkout.
- La Chutana is the visual/functional reference track and will grow to include more
  buildings, pit boxes, grandstands, 2D spectator cards, and additional assets.
- SVG must be canonical authority for topology and placements. Raster remains valid
  only as a derived preview, semantic mask, or heightfield artifact.
- Existing collision hard rules remain mandatory: continuous terrain heightfield,
  no deleted road cells, correct Blender +Z winding, exact narrow roadside collision
  bridge, safety floor, simplified barrier proxies, and no gameplay collision on
  vegetation/visual cards.

# OWNERSHIP
- SVG source: editor/server owns import, sanitization, canonicalization, saves,
  revision metadata and source hashes.
- Asset Registry: owns semantic asset IDs, allowed kinds, source paths, dimensions,
  previews, collision class, build budget and asset provenance.
- Normalizer/validator: owns schema validation, coordinate conversion, deterministic
  sampling, generated JSON and source/registry/compiler provenance.
- Blender compiler: owns mesh construction, terrain/road/collision generation,
  registered asset resolution, .blend output and GLB export.
- Godot: consumes only the activated generated GLB resources; it must not infer
  authoring information from Blender or SVG.
- Git revision service: owns scoped snapshots/commits for track-specific authoring
  files. It must not stage unrelated repository changes.

# KNOWN CONSTRAINTS
- Canonical editable source is SVG, not PNG, JSON, .blend or GLB.
- Use a restricted F90 SVG profile only. Accept at minimum the known-safe structural
  and geometry subset required by the editor (svg, g, path, polygon, polyline, line,
  circle, rect, metadata) and F90 `data-*` attributes. Reject scripts, event handlers,
  foreignObject, external references, image/use/iframe/audio/video, style/filter,
  animations, embedded fonts and unknown namespaces/elements.
- Define fixed coordinates: 1 SVG unit = 1 metre. The profile must state an immutable
  `viewBox`, axis convention, and SVG-to-Godot/Blender conversion. Do not rely on CSS
  pixels, browser tessellation, implicit transforms, or Blender import behavior.
- Canonicalization must expand allowed transforms, use explicit absolute path commands,
  deterministically order layers/elements/attributes, normalize decimals, and assign
  stable instance IDs. Compile from canonical data with project math, never rendered SVG.
- Centerline must be closed and have an own deterministic arc-length sampler. If Bézier
  paths are supported, define a fixed flattening tolerance and sampling rule.
- Store elevation and bank controls against centerline distance `s` (metres), not pixel
  positions. Store terrain edits as deterministic SVG-owned stamps/zones/parameters;
  generate the RF/RH heightfield during normalization/build.
- Preserve the stage gate: Base build requires human validation before procedural or
  decorative build. Do not run Blender after validation failure.
- Preserve split runtime GLBs for environment/collision versus collision-free vegetation
  until evidence supports a different Godot import budget.
- Cards, spectator stands, trees, grass, bushes, signs, flags and similar visual props
  remain collision-free. Detailed barrier visuals cannot be their collision geometry.
- Generated texture Forge images are not source authority; retain recipes/hashes instead.
- Preserve unrelated dirty worktree changes. Never reset, checkout, stage or commit
  unrelated files.

# DO NOT MODIFY
- Do not modify vehicle/GEVP/Jordan physics to compensate for track failures.
- Do not remove the continuous terrain collision, exact roadside collision bridge, or

- Do not replace Blender as the deterministic final compiler in the MVP.
- Do not make .blend, GLB, generated JSON, generated PNG, or a raw third-party SVG a

- Do not implement Three.js/editor-3D, automatic scatter as authority, road painter,
  pitlane, AI, weather or a Blender replacement in the MVP.
- Do not run a destructive Git operation or automatic broad commit.

# REJECTED HYPOTHESES
REJECTED HYPOTHESIS: The existing PNG layout should remain the editable authority for
the complete editor.
EVIDENCE: La Chutana's current resolution and world bounds produce roughly 0.30 m per
pixel. Raster masks also cannot express exact centerline curves, elevation/bank controls
or stable individual placement data without an additional parallel data model.
NEW VERIFIED FACT: PNG is suitable as a derived preview/mask/height artifact, not as the
authoritative source for precise manual track authoring.
STATUS: Do not revisit without a project requirement favoring raster painting over exact
topology and controls.

REJECTED HYPOTHESIS: Raw AI-generated SVG can be passed directly to Blender/build tools.
EVIDENCE: SVG permits executable, referenced, styled and mixed content beyond required
track geometry; imported SVG format/coordinate conventions are not controlled.
NEW VERIFIED FACT: Import must sanitize and canonicalize to the F90 SVG profile.
STATUS: Do not revisit without a verified safe import boundary and deterministic schema.

REJECTED HYPOTHESIS: A rendered/build GLB or .blend can be a second editable source.
EVIDENCE: Two editable authorities would break reproducibility and Git source history.
NEW VERIFIED FACT: .blend and GLBs must be generated output tied to provenance hashes.
STATUS: Do not revisit without an explicit bidirectional round-trip design.

# ACCEPTANCE CRITERIA
PASS only when all are true:
1. A valid external SVG is sanitized into a canonical F90 Track SVG; unsafe/unsupported
   input is rejected with actionable diagnostics.
2. The SVG alone, plus immutable registry/compiler versions, deterministically generates
   byte-identical normalized JSON across two runs.
3. The editor supports required user-controlled topology, banking/elevation controls,
   zones and individual/zone-based asset placement, including undo/redo.
4. Every intentional save creates a scoped immutable revision and a Git-tracked commit
   or documented equivalent Git object; restoring a revision is additive and safe.
5. Invalid/dirty/stale source cannot invoke Blender. Build requires explicit human
   action/approval and validated hash match.
6. Base and procedural stage gates remain enforced.
7. Generated terrain/collision preserves all existing hard collision contracts.
8. The output includes a generated .blend and GLB runtime parts with manifests/hashes;
   only validated complete parts are atomically activated for Godot.
9. La Chutana migrates with verified parity for its baseline, then supports added
   buildings, boxes, grandstands and 2D spectator cards within declared budgets.
10. Godot loads the activated output and visual acceptance is explicitly confirmed by a
    human or image-capable reviewer.

FAIL if any source is silently altered, SVG/JSON/.blend/GLB become competing editable
authorities, validation is bypassed, generated content receives unintended collision,
an invalid source reaches Blender, or publication leaves partially activated output.

INCONCLUSIVE if deterministic tests pass but no visual reviewer has accepted the result,
or if complete build/Godot validation cannot run in the available environment.
